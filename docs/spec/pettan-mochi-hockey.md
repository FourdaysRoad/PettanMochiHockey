## 2. コア・ゲームループ

1. **拾う・育てる（Collect & Grow）**：餅をドリブルしながらリンク上の「もち米」を集め、餅を巨大化（高得点化）させる。
2. **狙う・運ぶ（Risk & Carry）**：餅が大きいほど得点は高いが、移動速度が落ち、狙われやすくなる。
3. **殴る・奪う（Pettan & Steal）**：相手を杵で殴ると、相手は吹っ飛んで壁に「2Dペッタンコ」状態で張り付き、餅はその場に落ちる。
4. **決める（Score）**：奪った餅を相手の「臼型ゴール」に叩き込む。

## 3. 操作方法

スティック＋3ボタンで完結するシンプルな設計とする。入力は Unity Input System で実装する。

| 入力（ゲームパッド） | アクション | 仕様 |
|---|---|---|
| 左スティック | スケート移動 | 氷上を滑る慣性のある移動。急な方向転換時に氷しぶきVFXを出す |
| （正面接触） | モチ・ドリブル | 餅に近づくと杵の先に吸着（マグネット判定）し、自動で運ぶ |
| A（South） | パス／シュート | 餅を持っているときに前方へ打ち出す。長押しでチャージショット |
| B（East） | 杵スイング（Pettan攻撃） | 杵を水平に振る。相手に当たると吹っ飛ばし、餅を落とさせる。空振りすると隙ができる |
| R（RB/R1） | ダッシュ | スタミナを消費して瞬間的に加速する |
| Start | ポーズ | ポーズメニューを開く |

## 4. コアシステム仕様

### 4.1 もち米と餅の巨大化

- フィールド上に「もち米（光る米粒の塊）」を常に5〜10個出現させる。出現位置はランダムだが、ゴール内や壁の中は除く。
- 出現間隔：【要確認】（案：1.5秒ごとに、上限に達するまで補充）
- 餅をドリブルしている状態でもち米に触れると吸収し、餅が段階的に成長する。
- 餅を持っていないプレイヤーがもち米に触れた場合：【要確認】（案：何も起きない／素通りする）

| 段階 | 累計もち米数 | 餅サイズ | ゴール得点 | 保持者の移動速度 | 特徴 |
|---|---|---|---|---|---|
| Lv.1 小餅 | 0〜2 | 1.0倍 | 1点 | 100% | 軽く速攻向き |
| Lv.2 大餅 | 3〜5 | 1.5倍 | 2点 | 90% | シュート速度と当たり判定が強化される |
| Lv.3 鏡餅 | 6以上 | 2.5倍 | 3点 | 75% | シュート時にゴール前の敵を巻き込んで吹き飛ばす（貫通） |

- 餅のレベルとサイズは、餅が落ちたり奪われたりしても維持する。
- ゴールが決まると餅は消え、中央にLv.1の小餅を出し直す（出し直しまでの待ち時間【要確認】、案：1.0秒）。
- Lv.3の「巻き込み」で吹き飛ばされた敵も、Pettanステート（4.2）に入るか：【要確認】
- サイズ変更時は、見た目のスケールとコライダーを一緒に変える。

### 4.2 カートゥーン・クラッシュ「Pettan!!!」

杵スイングが相手に当たったときの演出と、被弾した側の状態遷移。物理挙動が暴れないよう、ステートマシンで制御する。

| ステート | 時間（被弾時点からの経過） | 挙動 |
|---|---|---|
| ① HitStop | 0.00〜0.08秒 | 0.08秒のヒットストップ。当たった位置に「Pettan!!!」吹き出しVFXをビルボード表示する。被弾者が餅を持っていれば保持を即解除し、餅はサイズを保ったままその場で軽く跳ねて落ちる |
| ② Launched | 0.08〜0.6秒 | 被弾者は操作できなくなる。攻撃者の正面方向へ高速で直線的に吹っ飛び、床か壁で1回バウンドしてからリンク外周の壁へ向かう |
| ③ Stuck | 壁に当たった時点〜2.6秒 | 壁に当たった瞬間に停止する（Rigidbody.isKinematic = true）。壁の法線に合わせて向きを固定し、スケールを (1.3, 1.3, 0.05) にして壁に貼ったシールのような見た目にする |
| ③' SlideDown（③の後半） | 1.5〜2.6秒 | 張り付いたまま、壁に沿って少しずつ下へずり落ちる |
| ④ Recover | 2.6秒 | 「ポンッ！」SEとともにスケールを (1.0, 1.0, 1.0) に戻す |
| ⑤ Invincible | 2.6〜3.6秒 | 1秒間、無敵の点滅状態で操作に復帰する |

**決めておくべきエッジケース**【要確認】
- 0.6秒たっても壁に届かない場合（リンク中央付近で被弾したときなど）の扱い（案：届くまで②を延長する／0.6秒の時点で一番近い壁へ移動させる）
- 吹っ飛び中に他のプレイヤーに当たった場合の扱い（案：すり抜ける）
- 張り付き中や無敵中に再び攻撃された場合（案：当たらない）
- 2人が同時に殴り合った場合（案：両方が被弾する）
- 2vs2で味方を殴った場合（案：当たらない）
- 張り付き中のコライダーの扱い（案：無効にする）
- 企画アセットにある「ピヨり（めまい）」アニメーションを、どのステートで使うか

### 4.3 移動・ダッシュ・シュート

| パラメータ | 値 |
|---|---|
| 基本移動速度・加速度・摩擦（慣性） | 【要確認】調整用パラメータとして外に出す |
| スタミナ最大値／ダッシュ1回の消費量／回復速度 | 【要確認】 |
| チャージショットの最大チャージ時間・段階数 | 【要確認】（案：1.0秒で最大、2段階） |
| 杵スイングの発生・持続・硬直（空振り時の隙） | 【要確認】 |
| パス・シュートした直後に、同じプレイヤーが餅を再吸着できない時間 | 【要確認】（案：0.3秒） |

- 調整用の数値はすべて ScriptableObject（例：`GameBalanceConfig`）にまとめ、コードに直接書かない。

### 4.4 試合ルール

- 試合時間は3分。時間切れの時点で得点の多いチームの勝ち。
- 同点の場合はサドンデス「ゴールデン・モチ」とし、次に得点したチームの勝ち（制限時間なし【要確認】）。
- キックオフでは中央にLv.1の小餅を置き、各プレイヤーを自陣の初期位置に配置する。ゴールが決まったあとも同じ配置に戻すかは【要確認】。
- 自陣のゴールに入れてしまった場合（オウンゴール）は、相手チームに得点を与える【要確認】。

## 5. 画面構成・UI・カメラ

### 5.1 画面遷移

```
起動（ローディング）→ タイトル（「クリック／ボタンでスタート」）→ 対戦設定（人数・チーム・デバイス割り当て）
→ 試合 ⇄ ポーズ → リザルト → （もう一度／タイトルへ）
```
- ブラウザはユーザーが操作するまで音を鳴らせないため、タイトル画面での最初のクリックやキー入力を「音声を有効にするきっかけ」として使う。

### 5.2 カメラ
- Cinemachine の Target Group を使い、全プレイヤーと餅が常に画面に収まるよう、位置と画角を自動で調整する斜め見下ろしカメラにする。
- 最小・最大のズーム範囲を決めて、極端に寄ったり引いたりしないようにする。

### 5.3 試合中のUI（uGUI または UI Toolkit【要確認】）
- 画面上部中央：両チームのスコアと残り時間
- 餅の頭上：レベル（Lv.1〜3）、得点倍率（×1〜×3）、次の成長までのゲージ
- プレイヤーの足元：1P〜4Pの識別リング、スタミナゲージ、チャージゲージ
- ゴール時：「GOAL!」演出と獲得点数の表示

### 5.4 画面サイズ
- 16:9を基準とし、ブラウザのウィンドウサイズに合わせて表示を調整する。フルスクリーンボタンを用意する。

## 7. Unity実装アーキテクチャ

### 7.1 基本方針
- **ゲームロジックは純粋なC#クラスに分ける**。UnityEngine に依存しない Core 層（得点計算、餅の成長判定、Pettanステートの時間進行、試合タイマー、ルール判定）を作り、EditModeテストで高速にTDDを回す。
- MonoBehaviour は「入力」「物理」「見た目」と Core 層をつなぐ薄い層にとどめる。
- Assembly Definition でレイヤーを分ける。

| アセンブリ | 内容 | 依存先 |
|---|---|---|
| `MochiHockey.Core` | 純粋なロジック（noEngineReferences = true） | なし |
| `MochiHockey.Runtime` | MonoBehaviour、物理、入力、VFX、UI | Core |
| `MochiHockey.Tests.EditMode` | Core の単体テスト | Core |
| `MochiHockey.Tests.PlayMode` | 物理挙動や統合動作のテスト | Runtime, Core |

### 7.2 主要コンポーネント

| クラス | 層 | 役割 |
|---|---|---|
| `MochiGrowth` | Core | もち米の数からレベル・得点・速度補正・サイズを求める |
| `PettanStateMachine` | Core | 被弾後のステート（HitStop→Launched→Stuck→Recover→Invincible）を時間で進める |
| `MatchRules` / `MatchTimer` | Core | スコア、試合時間、サドンデス、勝敗判定 |
| `GameBalanceConfig` | Runtime（ScriptableObject） | 調整用パラメータの置き場 |
| `PlayerController` | Runtime | Rigidbody.AddForce による慣性移動、ダッシュ、杵の当たり判定の有効化、PettanStateMachine に応じた見た目と物理の制御 |
| `MochiBall` | Runtime | 保持者の管理、持たれていないときの物理挙動、もち米との接触、`Drop()`、サイズ反映 |
| `MochiRiceSpawner` | Runtime | もち米を定期的に生成し、オブジェクトプールで使い回す |
| `GoalPost` | Runtime | 餅が入ったことを検知し、MatchRules に得点を伝える |
| `MatchManager` | Runtime | キックオフ、ゴール後の再開、画面遷移の管理 |
| `PlayerJoinManager` | Runtime | Input System の PlayerInputManager を使った参加受付とデバイス割り当て |
| `HudPresenter` | Runtime | スコア、タイマー、各種ゲージの表示 |

## 9. ビルド・デプロイ要件

### 9.1 WebGLビルド設定
- 圧縮形式：Gzip または Brotli とし、**Decompression Fallback を有効にする**。GitHub Pages では Content-Encoding ヘッダーを設定できないため。
- Exception Support は製品ビルドで最小限にする（デバッグビルドでは有効）。
- ローディング画面は WebGL テンプレートをカスタマイズして作る（タイトルロゴと進捗バー）。

### 9.2 CI/CD（GitHub Actions）
1. Pull Request のとき：EditModeとPlayModeのテストを実行する（GameCI unity-test-runner）。
2. main ブランチへの push のとき：テスト → WebGLビルド（GameCI unity-builder）→ `actions/upload-pages-artifact` → `actions/deploy-pages` で GitHub Pages に公開する。
3. 必要な Secrets：`UNITY_LICENSE`、`UNITY_EMAIL`、`UNITY_PASSWORD`。
4. Library フォルダをキャッシュして、ビルドを速くする。
- 公開URL：`https://<ユーザー名>.github.io/<リポジトリ名>/`

### 9.3 リポジトリ
- Unity 用の `.gitignore`（Library、Temp、Logs、Builds など）と、Git LFS の設定（`.gitattributes`）を用意する。
- Asset Store から入れた有料アセットを公開リポジトリに含めてよいかは、ライセンスを確認して判断する【要確認：リポジトリを公開にするか非公開にするか】。
