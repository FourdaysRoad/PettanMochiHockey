# pettan-mochi-hockey 要件定義書（軽量版）

## 概要

「Pettan! MOCHI HOCKEY」は、PC ブラウザ（Unity WebGL）で 2〜4 人がローカル対戦する 3D カートゥーン・パーティスポーツゲームである。プレイヤーは氷上のリンクで餅をドリブルしながら「もち米」を集めて餅を巨大化させ、杵で相手を殴って壁に「ペッタンコ」に張り付かせて餅を奪い、相手の臼型ゴールに叩き込んで得点する。初期リリースでは CPU 対戦・オンライン対戦は対象外とする。

### 必須機能（Must Have）

#### A. 試合ルール
- REQ-001: システムは 1 試合を 3 分とし、時間切れ時点で得点の多いチームを勝者としなければならない 🔵 *PRD 1章・4.4*
- REQ-002: 時間切れ時点で同点の場合、システムはサドンデス「ゴールデン・モチ」に移行し、次に得点したチームを勝者としなければならない（制限時間なし） 🔵 *PRD 4.4・ヒアリング Q3（案を採用）*
- REQ-003: 餅がゴールに入った場合、システムはゴールを守る側の相手チームに、餅のレベルに応じた得点（Lv.1=1点、Lv.2=2点、Lv.3=3点）を加算しなければならない。オウンゴールも相手チームの得点とする 🔵 *PRD 4.1・4.4・ヒアリング Q3*
- REQ-004: ゴールが決まった場合、システムは餅を消し、1.0 秒後に中央へ Lv.1 の小餅を出し直さなければならない。プレイヤーの位置は初期位置に戻さず、各プレイヤーの状態（張り付き中など）もそのまま継続する 🔵 *PRD 4.1・ヒアリング Q3・Q8*
- REQ-005: キックオフ（試合開始時）には、システムは中央に Lv.1 の小餅を置き、各プレイヤーを自陣の初期位置に配置しなければならない 🔵 *PRD 4.4*
- REQ-006: 対戦形式は 1vs1 と 2vs2 とし、味方への杵攻撃は当たらないものとしなければならない 🔵 *PRD 1章・4.2・ヒアリング Q3*

#### B. 餅ともち米
- REQ-011: システムはフィールド上に「もち米」を常に 5〜10 個出現させ、上限に達するまで 1.5 秒ごとに補充しなければならない。出現位置はランダムだが、ゴール内や壁の中は除く 🔵 *PRD 4.1・ヒアリング Q3*
- REQ-012: 餅をドリブル中のプレイヤーがもち米に触れた場合、システムはもち米を吸収し、餅の累計もち米数を 1 増やさなければならない。餅を持っていないプレイヤーが触れても何も起きない 🔵 *PRD 4.1・ヒアリング Q3*
- REQ-013: システムは累計もち米数から餅のレベルを決めなければならない（0〜2=Lv.1 小餅／3〜5=Lv.2 大餅／6以上=Lv.3 鏡餅）。サイズ倍率（1.0／1.5／2.5）・得点・保持者の移動速度（100%／90%／75%）はレベルに従い、見た目とコライダーを一緒に変える 🔵 *PRD 4.1*
- REQ-014: 餅のレベルとサイズは、落ちたり奪われたりしても維持しなければならない 🔵 *PRD 4.1*
- REQ-015: Lv.2 の餅はシュート速度と当たり判定を強化し、Lv.3 の餅はシュート時にゴール前の敵を巻き込んで吹き飛ばさなければならない（巻き込まれた敵は Pettan ステートに入る） 🔵 *PRD 4.1・ヒアリング Q6*

#### C. プレイヤー操作
- REQ-021: システムは左スティック（または移動キー）で、慣性のあるスケート移動を行わなければならない 🔵 *PRD 3章*
- REQ-022: プレイヤーが餅に正面から近づいた場合、システムは餅を杵の先に吸着させ、自動でドリブルさせなければならない 🔵 *PRD 3章*
- REQ-023: 餅を持っているときにパス／シュートボタンを押した場合、システムは餅を前方へ打ち出さなければならない。長押しでチャージショットとし、最大 1.0 秒・2 段階とする 🔵 *PRD 3章・4.3・ヒアリング Q3*
- REQ-024: パス・シュートした直後 0.3 秒間、システムは同じプレイヤーが餅を再吸着できないようにしなければならない 🔵 *PRD 4.3・ヒアリング Q3*
- REQ-025: 杵スイングボタンを押した場合、システムは杵を水平に振り、相手に当たれば Pettan ステートに移行させ、空振りの場合は硬直（隙）を発生させなければならない 🔵 *PRD 3章*
- REQ-026: ダッシュボタンを押した場合、システムはスタミナを消費して瞬間的に加速しなければならない。スタミナが足りない場合はダッシュしない 🔵 *PRD 3章*（スタミナ不足時の挙動は 🟡 妥当な推測）
- REQ-027: Start（ポーズ）を押した場合、システムは試合を一時停止してポーズメニューを開かなければならない 🔵 *PRD 3章*

#### D. Pettan（被弾）ステート
- REQ-031: 杵が相手に当たった場合、システムは被弾者を次の順にステート遷移させなければならない：HitStop（0.00〜0.08秒）→ Launched（0.08〜壁到達）→ Stuck（壁到達〜2.6秒、1.5秒以降は SlideDown）→ Recover（2.6秒）→ Invincible（2.6〜3.6秒） 🔵 *PRD 4.2*
- REQ-032: HitStop に入った時点で被弾者が餅を持っていた場合、システムは保持を即解除し、餅をサイズを保ったままその場で軽く跳ねて落とさなければならない 🔵 *PRD 4.2*
- REQ-033: Launched 中、被弾者は操作できず、攻撃者の正面方向へ吹っ飛び、床か壁で 1 回バウンドしてからリンク外周の壁へ向かわなければならない。0.6 秒たっても壁に届かない場合は、壁に当たるまで Launched を延長する（上限時間を超えたらその場で Recover へ） 🔵 *PRD 4.2・ヒアリング Q5*（上限時間は 🟡 妥当な推測）
  - 実装の決定（2026-11-18、ユーザー指示）：床でははねず、水平にまっすぐ飛んで壁で 1 回跳ね返り、次に当たった壁に貼り付く
- REQ-034: Stuck に入った場合、システムは被弾者を停止させ、壁の法線に合わせて向きを固定し、スケールを (1.3, 1.3, 0.05) にしなければならない。Recover 時に「ポンッ！」SE とともに (1.0, 1.0, 1.0) に戻す 🔵 *PRD 4.2*
- REQ-035: Launched・Stuck・Invincible 中のプレイヤーは杵攻撃を受けず、Launched 中は他のプレイヤーをすり抜け、Stuck 中はコライダーを無効にしなければならない 🔵 *PRD 4.2・ヒアリング Q3*
- REQ-036: 2 人が同時に杵を当て合った場合、システムは両方を被弾させなければならない 🔵 *PRD 4.2・ヒアリング Q3*

#### E. 参加受付・入力デバイス
- REQ-041: 対戦設定画面では、システムはボタンを押したデバイスから順にプレイヤーとして参加させ、人数（2〜4人）とチームを決められるようにしなければならない 🔵 *PRD 3.1・5.1*
- REQ-042: キーボードは P1: WASD + J/K/L、P2: 矢印キー + テンキー1/2/3 とし、3〜4 人で遊ぶ場合はゲームパッドを使う 🔵 *PRD 3.1・ヒアリング Q9*
- REQ-043: システムは、ゲームパッドはボタンを一度押すまで認識されないことを画面上で案内しなければならない 🔵 *PRD 3.1*

#### F. 画面遷移・UI・カメラ
- REQ-051: システムは「ローディング → タイトル → 対戦設定 → 試合 ⇄ ポーズ → リザルト →（もう一度／タイトルへ）」の画面遷移を提供しなければならない 🔵 *PRD 5.1*
- REQ-052: システムはタイトル画面での最初のクリック・キー入力をきっかけに音声を有効にしなければならない 🔵 *PRD 5.1*
- REQ-053: 試合中、システムはスコアと残り時間（画面上部中央）、餅のレベル・得点倍率・成長ゲージ（餅の頭上）、プレイヤー番号リング・スタミナ・チャージゲージ（足元）、ゴール時の「GOAL!」演出を表示しなければならない 🔵 *PRD 5.3*
- REQ-054: カメラは全プレイヤーと餅が常に画面に収まるよう、最小・最大ズームの範囲内で位置と画角を自動調整する斜め見下ろしにしなければならない 🔵 *PRD 5.2*
- REQ-055: 画面は 16:9 を基準にブラウザのウィンドウサイズへ合わせ、フルスクリーンボタンを用意しなければならない 🔵 *PRD 5.4*
- REQ-056: キックオフ（試合開始前）の間、システムは残り秒数を「3・2・1」と大きく表示して「ピッ」と鳴らし、試合が始まったら「GO!」を短く表示して笛を鳴らさなければならない 🔵 *2026-11-19 ユーザー追加要望*

#### G. ビルド・公開
- REQ-061: main ブランチへの push 時、システムは CI でテストを実行し、WebGL ビルドを GitHub Pages に公開しなければならない。Pull Request では EditMode・PlayMode テストを実行する 🔵 *PRD 9.2*
- REQ-062: WebGL ビルドは Gzip または Brotli で圧縮し、Decompression Fallback を有効にしなければならない 🔵 *PRD 9.1*
- REQ-063: ローディング画面はカスタム WebGL テンプレートでタイトルロゴと進捗バーを表示しなければならない 🔵 *PRD 9.1*

### 基本的な制約

- REQ-401: ゲームロジック（得点計算、餅の成長判定、Pettan ステートの時間進行、試合タイマー、ルール判定）は UnityEngine 非依存の `MochiHockey.Core` に置き、EditMode テストを先に書かなければならない 🔵 *CLAUDE.md・PRD 7.1*
- REQ-402: 調整用の数値はすべて `GameBalanceConfig`（ScriptableObject）に置き、コードに直接書いてはならない 🔵 *CLAUDE.md・PRD 4.3*
- REQ-403: WebGL で使えない機能（スレッド、System.IO によるファイル操作、通常のソケット通信、Compute Shader への依存）を使ってはならない 🔵 *CLAUDE.md・PRD 10章*
- REQ-404: 保存するのは設定値のみとし、PlayerPrefs を使う 🔵 *PRD 1.1*
- REQ-405: 対象外：オンライン対戦、CPU 対戦、モバイル・タッチ操作、Steam／コンソール、アカウント・ランキング 🔵 *PRD 1.1・ヒアリング Q2*

**そうすることで** リスクとリターンの駆け引きを楽しめる

**私は** プレイヤー **として**

**そうすることで** 笑える逆転劇が生まれる

**関連要件**: REQ-053〜055

## 基本的な受け入れ基準

### REQ-013: 餅のレベル判定 🔵
**Given**: 累計もち米数 n の餅がある
**When**: レベルを問い合わせる
**Then**: n=0〜2 → Lv.1（1点・速度100%・1.0倍）、3〜5 → Lv.2（2点・90%・1.5倍）、6以上 → Lv.3（3点・75%・2.5倍）が返る

**テストケース**:
- [ ] 正常系: n=0, 2, 3, 5, 6, 10 で境界ごとに正しいレベルになる
- [ ] 主要な異常系: n が負の値のときは例外または Lv.1 扱い（設計で決める） 🟡

### REQ-031: Pettan ステート遷移 🔵
**Given**: 被弾したプレイヤーの PettanStateMachine
**When**: 時間を進める（壁到達イベントを含む）
**Then**: 0.08秒で HitStop→Launched、壁到達で Stuck、1.5秒で SlideDown、2.6秒で Recover、3.6秒で通常状態に戻る

**テストケース**:
- [ ] 正常系: 0.5秒で壁到達した場合の各時刻のステート
- [ ] 主要な異常系: 0.6秒を過ぎても壁に届かない場合に Launched が延長され、上限時間で Recover する

### REQ-001/002: 試合タイマーとサドンデス 🔵
**Given**: 試合が開始された MatchRules
**When**: 180 秒経過する
**Then**: 得点差があれば勝者が決まり、同点ならサドンデスに移行し、次の得点で勝者が決まる

**テストケース**:
- [ ] 正常系: 2-1 で時間切れ → 2 点のチームが勝つ
- [ ] 主要な異常系: 1-1 で時間切れ → サドンデス、ゴールで即終了

### REQ-003: 得点 🔵
**Given**: Lv.2 の餅
**When**: チーム A のゴールに入る（オウンゴール含む）
**Then**: チーム B に 2 点が入る

**テストケース**:
- [ ] 正常系: Lv.1/2/3 それぞれで 1/2/3 点が相手チームに入る
- [ ] 主要な異常系: オウンゴールでも相手チームに得点が入る

### REQ-061: 自動デプロイ 🔵
**Given**: main ブランチに push する
**When**: GitHub Actions が実行される
**Then**: テストが通り、`https://fourdaysroad.github.io/PettanMochiHockey/` で最新ビルドが遊べる

**テストケース**:
- [ ] 正常系: 空のシーンが GitHub Pages で表示される（マイルストーン Step 0）
- [ ] 主要な異常系: テストが失敗した場合はデプロイされない 🟡

## 最小限の非機能要件

- **パフォーマンス**: 中程度の性能の PC で、4 人対戦中も 60fps を目標にする。入力から画面反映まで 3 フレーム以内 🔵 *PRD 6章*
- **ビルドサイズ・ロード**: 圧縮後の初回ダウンロード 50MB 以下、一般的な回線で 15 秒以内（案を採用）。ロード中は進捗バーを表示 🟡 *PRD 6章の案*
- **対応ブラウザ**: PC 版 Chrome／Edge 最新版は必須、Firefox は努力目標（動作確認のみ）、Safari は対象外。WebGL 2.0 🔵 *PRD 6章・ヒアリング Q4*
- **アクセシビリティ**: プレイヤー識別は色だけでなく番号（1P〜4P）も表示する 🔵 *PRD 6章*
- **セキュリティ**: サーバー・個人情報なし。Unity ライセンス情報は GitHub Secrets のみで管理する 🔵 *PRD 9.2*
